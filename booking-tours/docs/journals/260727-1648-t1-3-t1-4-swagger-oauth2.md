# T1.3 + T1.4: Swagger + OAuth2 Facebook/Twitter

**Date**: 2026-07-27 17:26
**Severity**: Medium
**Component**: API Documentation, OAuth2 Authentication
**Status**: Resolved

## What Happened

Completed dual setup: OpenAPI 3.0 documentation via Swagger and standard OAuth2 providers for Facebook and Twitter. Reviewer caught three correctness bugs during integration test; all fixed in place and verified.

## The Brutal Truth

The Twitter integration broke JWT subjects hard — every login produced garbage because we sourced the user identity from a nested Map object instead of a clean attribute. The stale Facebook config couldn't fetch names or emails. Both felt like they should have been caught before hitting review; the OAuth2 provider ecosystem rewards copy-paste mistakes.

## Technical Details

**Swagger:**
- springdoc-openapi-starter-webmvc-ui:2.6.0 added to pom.xml
- SwaggerConfig.java: JWT Cookie security scheme (APIKEY in cookie)
- /swagger-ui/**, /v3/api-docs/** permitted in SecurityConfig
- Disabled in prod + test; UI only at /swagger-ui.html in dev
- All 14 controllers annotated with @Tag + @Operation

**OAuth2 Bugs Fixed:**

1. **Twitter JWT subject (High)**: nameAttributeKey="data" returned Map.toString() of nested Twitter object, breaking all authenticated requests. Fix: inject synthetic_email attribute; use as nameAttributeKey. Twitter has no email endpoint → fallback to `twitter_{username}@noemail.local`.

2. **Facebook null fields (High)**: Graph API returns only id by default. Fix: add `?fields=id,name,email` to user-info-uri in application*.properties across all profiles.

3. **PII in logs (Medium)**: User email logged at INFO in prod. Fix: log userId + role only.

## Root Cause Analysis

**Twitter:** Misread the data shape. Standard OAuth2 puts user attributes flat; Twitter's Graph API nests them, but we didn't synthesize the mapping properly before using the response.

**Facebook:** Copied minimal config without reading that Graph API requires explicit field names.

**Logging:** Didn't filter fields before sending to logs when adding OAuth2 user payloads.

## Lessons Learned

- Stub out OAuth2 providers in test/dev configs early — missing fields hide until the first login attempt.
- Trace user attribute mapping through the full pipeline: raw API response → mapper → authentication.getName() → JWT subject. One weak link breaks auth everywhere.
- Standard OAuth2 UserService chains need docstring on the nameAttributeKey and what it pulls from the API response.

## Next Steps

- PII filtering should move into a logging interceptor so it doesn't leak on profile updates or future endpoints.
- Add integration tests for Facebook/Twitter logins before merging to main (currently none exist).
